## 三、卡点根因 & 已排除的方案（省去重启后再次试错）

1. **本机无可用 Gradle**：`~/.gradle/wrapper/dists` 下 8.7/8.11.1/8.13/9.1.0 全都有 dists 目录，但**均未真正解包**（只有 `docs/`，无 `bin/gradle`、无 zip）。之前误判"未解包"是 find 深度不够，实际确认是空壳 → 无法借用任何本地 Gradle。
2. **镜像全死**：腾讯云/华为云 `gradle-8.7-bin.zip` 返回 200/206 但 **0 字节**（完整 GET 与 Range 都 0）；清华/Aliyun 路径 404。
3. **官方源走 307→github 302→release-assets.githubusercontent.com（Azure CDN，带 60 分钟 SAS token）**：
   - Gradle wrapper 的 Java 下载器能稳定拉，但 **~17KB/s**（靠前面 29 分钟只下到 30MB）。
   - 直接用 `curl -L -r` 单连接偶尔能到 76KB/s，但**极不稳定**（多次 0 字节，CDN 对并发/重定向丢数据）。
   - GitHub 文件代理（ghproxy.com / mirror.ghproxy.com / github.moeyy.xyz / gh.api.99988866.xyz）在关机前最后一次测试**未返回数据**，未验证可用，重启后可再试。
4. **AGP 8.5.2 要求 Gradle ≥ 8.6**，故 wrapper 指定的 8.7 是合适版本；8.11.1/8.13/9.1.0 也兼容但同样未解包，且 wrapper 只认 distributionUrl 指定的 8.7。

## 五、重启后恢复步骤（按顺序）

```bash
# 0. 重连手机，复核设备
adb devices            # 应见 ZY22DDK2FL  device

# 1. 进入工作区，设 JDK（Unix 风格 PATH 关键）
cd /f/KTV
export JAVA_HOME=/c/Users/ew/jdk17
export ANDROID_HOME=/c/Users/ew/AppData/Local/Android/Sdk
export PATH=/c/Users/ew/jdk17/bin:$PATH
java -version          # 须成功打印 17.x

# 2. 触发 Gradle 8.7 下载+构建（放后台，前台轮询）
#    若网络正常，wrapper 自动下 8.7(~110-128MB) 并解包编译。
./gradlew assembleDebug --console=plain --no-daemon > /f/KTV/build_apk_run.log 2>&1 &
# 前台轮询：
#   watch -n 20 'ls -la ~/.gradle/wrapper/dists/gradle-8.7-bin/*/gradle-8.7-bin.zip.part'
#   或 tail -f /f/KTV/build_apk_run.log

# 2b. 若官方源过慢（>30KB/s 且预计 >60min），重启后优先试 GitHub 代理：
#   改 gradle/wrapper/gradle-wrapper.properties 的 distributionUrl 为
#   https://mirror.ghproxy.com/https://services.gradle.org/distributions/gradle-8.7-bin.zip
#   （或直接指向 github release：.../releases/download/v8.7.0/gradle-8.7-bin.zip 经某代理）
#   再跑 ./gradlew assembleDebug。代理可用性需实测，哪个通就用哪个。

# 3. 构建成功产物
ls -la /f/KTV/app/build/outputs/apk/debug/app-debug.apk

# 4. 装真机
adb -s ZY22DDK2FL install -r /f/KTV/app/build/outputs/apk/debug/app-debug.apk

# 5. 启动 + 抓日志
adb -s ZY22DDK2FL shell am start -n com.yuexiao12.sensorguard/.MainActivity
adb -s ZY22DDK2FL logcat -s SG:* *:S      # 另开终端持续看
```
