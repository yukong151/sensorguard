# P0-1 规则引擎误报修复

> 对应任务 #26/#27/#28（探查 + 摇一摇识别 + 系统豁免），验证任务 #29。
> 对照文档：`sensorguard_边缘计算及传感器安全的轻量级APP总开发开发文档 (3).md` §13。

## 1. 根因

`rule=112`（`category=side_channel` / `kind=observe` / `severity=40`）是 22 条历史告警里**绝大多数**的来源。它在 `rules.v1.json` 中的谓词只有一条：

```json
"predicates": [ { "op_in": [10, 11] } ]   // ACCEL / GYRO 任意连接即触发
```

没有任何 uid / 包名 / 采样率 / 持续时间限制，因此**任何加速度计或陀螺仪连接都无差别触发 OBSERVE**——
包括 Android 系统自身（已实测误报）：

- `uid=1000` 的 `com.android.server.telecom` → `FaceDownDetector`（翻转息屏）
- `uid=10213` 的 Google Play services（ActivityRecognition 加速度计）
- `com.android.systemui` 距离/方向传感器

此外，`system_proxy` 上下文字段在 `CtxProbe.snapshot()` 中**写死为 `false`**，从未据 uid/包名区分系统组件与普通 App，
导致即便给 R112 加 `system_proxy_equals:false` 谓词也无效（所有事件都是 false，仍然命中）。

## 2. 改动清单（5 处）

| # | 文件 | 改动 |
|---|---|---|
| 1 | `core-rust/src/rules.rs` (`builtin_rules`, R112) | 加 `Predicate::SystemProxyEquals(false)`，系统组件不再触发此 OBSERVE |
| 2 | `core-rust/rules/rules.v1.json` (R112) | 同步加 `{ "system_proxy_equals": false }`（`load_rules` 测试要求 JSON 与 `builtin_rules()` 同构） |
| 3 | `app/.../probe/ProbeModels.kt` (`CtxProbe.snapshot`) | 改签名 `(uid: Int, pkgName: String?)`，据 `uid<10000` 或包名 `android.`/`com.android.`/`com.google.android.` 体系 设 `systemProxy = true` |
| 4 | `app/.../service/GuardService.kt` (`pushProbeEvent`) | 调用改为 `CtxProbe.snapshot(ev.uid, ev.pkgName)` |
| 5 | `app/.../service/GuardService.kt` (`handleVerdicts`) | 新增 `upgradeAbuseVerdict` + `ABUSE_SDK_PATTERNS`，把命中摇一摇/广告 SDK 的 ACCEL/GYRO OBSERVE 升级为 ALERT |

### 2.5 `upgradeAbuseVerdict` 逻辑

```kotlin
private val ABUSE_SDK_PATTERNS = listOf(
    "com.zhihu.android.launch.view.shake", // 知乎摇一摇
    "com.youku.xadsdk.ui.shake",           // 优酷开屏摇一摇
    "com.pgl.ssdk",                        // Pangle 广告 SDK
    "com.facebook.ads",                    // Meta Audience Network
    "com.applovin",                        // AppLovin
    "com.bytedance.sdk.openadsdk",         // 穿山甲
    "com.qq.e.ads",                        // 优量汇
)

private fun upgradeAbuseVerdict(v: VerdictEntryData): VerdictEntryData {
    if (v.kind == SgEnum.VERDICT_ALERT) return v
    if (v.op != SgEnum.OP_ACCEL && v.op != SgEnum.OP_GYRO) return v
    val info = attributionFor(pkgHex(v.pkgHash)) ?: return v
    if (ABUSE_SDK_PATTERNS.none { info.first.contains(it) }) return v
    return v.copy(kind = SgEnum.VERDICT_ALERT, category = SgEnum.CAT_SIDE_CHANNEL,
                  severity = max(v.severity, 80), ruleId = 112)
}
```

## 3. 设计要点

- **为何系统豁免放 Rust 规则 + Kotlin 填 `systemProxy`**：`system_proxy` 是 fbs/FFI 已有字段，Rust 引擎 `eval_predicate` 已支持 `SystemProxyEquals`，
  复用它避免改动 FlatBuffers schema 与 JNI 桥接。
- **为何摇一摇识别放 Kotlin 后处理**：Rust 规则引擎只能拿到 `uid` + `pkg_hash`（包名在 Kotlin 侧被 hash 后才传入），
  无法按包名匹配；而 Kotlin 侧 `attributionFor(pkgHash)` 已能反查回原始包名，故在 `handleVerdicts` 落库前做升级最省事、零 fbs 改动。
- **未消除的噪声**：厂商预装 App（如 `com.motorola.launcher3` 方向监听）包名不属上述前缀，仍会 OBSERVE——属"普通 App 用运动传感器"合法提示范畴，非系统误报，本期不处理。

## 4. 验证计划（任务 #29）

1. 用户本机运行 `tools\build_apk.bat` 重新构建（沙箱无法构建，必须本机）。
2. agent 推送装机：`adb -s ZY22DDK2FL install -r app-debug.apk`。
3. 真机核对：
   - **系统误报消除**：`FaceDownDetector` / `SystemUI` / GMS 的 ACCEL/GYRO 不再出现在时间线告警中。
   - **摇一摇升级**：运行知乎/优酷等含摇一摇 SDK 的 App，对应事件在时间线应显示为 **ALERT（侧信道，severity≥80）**。
   - **普通 App 正常提示**：CapCut 等方向监听仍 OBSERVE（保留"提示"语义，符合开发阶段可见性要求）。
